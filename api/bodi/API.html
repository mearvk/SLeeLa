SLeeLa BODI XML API Reference

The BODI XML runtime reads a bounded XML project and turns its declared operations into witnessed, deterministic SLeeLa API calls. XML is a project representation; it is not arbitrary native-code execution.

Envelope

<bodi version="1">
  <project id="..." kind="science|email"/>
  ...
</bodi>

Science projects

A science project contains one or more discipline elements. Supported executable disciplines in this first API are math and physics. The schema also reserves descriptive discipline names such as chemistry, biology, astronomy, earth-science, computer-science, and engineering for future native handlers.

Operations use named functions and numeric arguments. Examples include math.sqrt, math.pow, math.sin, physics.velocity, physics.force, physics.kinetic_energy, physics.gravitational_force, physics.ohms_voltage, and physics.electric_power.

Email / SMTP projects

An email project declares an SMTP endpoint and a message. The password must be supplied by an environment variable through password-env; credentials are not intended to be stored in XML.

Supported TLS modes map directly to the existing Email Facade: none, starttls, and implicit. The runner requires --send-email before it performs network submission.

BODI witness

Every executed project operation produces a witness record containing project identity, sequence, discipline, operation, result, and status.

Execution boundary

The runtime performs an allow-listed operation dispatch. Unknown elements, disciplines, operations, malformed numbers, and excessive input are rejected. XML cannot invoke shell commands or arbitrary native functions.
