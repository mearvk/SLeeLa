SLeeLa Nordshrift API

Purpose: Nordshrift is the SLeeLa transpiler driver and semantic coordination layer. This API documents how a .sst sheet can carry the complete SLeeLa architectural input-object vocabulary.

Architecture Input Categories

  • core — memory, errors, strings, types, time, logging, configuration.
  • io — streams, buffers, console, files, serialization.
  • system — processes, threads, environment, permissions, platform facilities.
  • network — sockets, DNS, TCP, UDP, TLS, HTTP.
  • application — GUI, web, email, database, application services.
  • data — analytics, XML, JSON, records, structured data.
  • science — mathematics, physics, chemistry, analytics, and future disciplines.
  • security — hashing, cryptography, certificates, credentials, integrity.
  • deployment — configuration, installation, service lifecycle, health, deployment coordination.

Generic Input Object

The public semantic model is represented by input_object.h and input_object.cpp.

object <category> <identity>:
  type <type>
  source <source>
  target <target>
  value <value>
  inputs: [input, ...]
  outputs: [output, ...]
  property <name> <value>

InputObject Model

enum class InputObjectCategory {
    Core, IO, System, Network, Application,
    Data, Science, Security, Deployment
};

struct InputObject {
    InputObjectCategory category;
    std::string identity;
    std::string type;
    std::string source;
    std::string target;
    std::string value;
    std::vector<std::string> inputs;
    std::vector<std::string> outputs;
    std::map<std::string, std::string> properties;
    int line;
};

Validation Contract

  • Identity is required and limited to 256 characters.
  • Type is limited to 128 characters.
  • Source and target are limited to 4096 characters each.
  • Inputs, outputs, and properties are each limited to 64 members.
  • Unknown categories are rejected.
  • Unknown object members are rejected.
  • Malformed object declarations are rejected by the parser.

Relationship to SLeeLa APIs

The generic object layer provides a common input representation for the broader SLeeLa architecture. It complements specialized APIs rather than replacing them.

  • Core → foundational runtime APIs.
  • IO → file, stream, console, and serialization APIs.
  • System → process, thread, environment, permission, and platform APIs.
  • Network → socket, DNS, TLS, HTTP, POST, listener, and router APIs.
  • Application → GUI, web-server, email, and database APIs.
  • Data → data analytics, XML, JSON, and record APIs.
  • Science → math, physics, chemistry, and data-analysis disciplines.
  • Security → hashing, cryptography, certificates, credentials, and integrity APIs.
  • Deployment → web/database/application deployment and health APIs.

Existing Specialized Nordshrift Input

The generic object model complements the existing network, finance, reach, measure, and subject structures. Specialized structures retain their stronger domain-specific validation.

Execution Boundary

An input object is a validated declaration. Declaring an object does not implicitly open a socket, execute a process, modify a file, send email, connect to a database, or deploy a service. Actual side effects remain explicit operations behind their corresponding SLeeLa APIs and platform adapters.

Semantic Subject Model

Nordshrift also exposes the shared semantic chain:

Subject → Quantity → Unit → Assumption → Relation → Formula → Transformation → Result → ComparativeNorm → Evidence → Explanation → Validation
