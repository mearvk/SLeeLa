BigArrayGCVerify #sleela 2.5 (lib/math/examples/BigArrayGCVerify.sleela)

BigArrayGCVerify class

Regression guard for the incremental-GC allocate-black fix. It allocates two large int[] arrays and fills them in a long loop, which forces a garbage-collection cycle to run WHILE a second large array is being allocated and populated. Before the fix, an object allocated during the GC's marking phase was not on that cycle's root snapshot and was swept as garbage even though it was a live local -- surfacing as "index assignment on a non-array value" partway through the fill. This program must run to completion and report the expected last elements.

BigMulVerify #sleela 2.5 (lib/math/examples/BigMulVerify.sleela)

BigMulVerify class

Regression check for the native big-integer multiply (OP_BIGMUL). It multiplies the same operands two ways -- the native bigmul() bridge and a pure-SLeeLa schoolbook multiply -- across several operand sizes spanning the Karatsuba threshold, and asserts the limb arrays are identical. This guards the Karatsuba recombination (the z1 = z1 - z0 - z2 borrow, which must carry a borrow of up to two per limb) against silent regressions.
