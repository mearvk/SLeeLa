<p align="center"><strong>The Now. The Ingredient.</strong></p>

## Ελληνικά

Η SLeeLa είναι μια εγγενής γλώσσα προγραμματισμού συστημάτων, μαζί με μεταγλωττιστή, περιβάλλον εκτέλεσης και οικοσύστημα εικονικών μηχανών. Το έργο δεν περιορίζεται στη σύνταξη της γλώσσας: περιλαμβάνει βιβλιοθήκες, εργαλεία, διεπαφές, τεκμηρίωση, διαδικασίες κατασκευής και συμβάσεις για τις υποστηριζόμενες πλατφόρμες.

Η διεθνής έκδοση 3.0 συγκεντρώνει τη γλώσσα, το runtime, τα εργαλεία ανάπτυξης και τις βιβλιοθήκες. Τα τεχνικά αναγνωριστικά, ο πηγαίος κώδικας, οι εντολές, τα ονόματα αρχείων και τα ονόματα API διατηρούνται αμετάβλητα, ώστε τα παραδείγματα να μπορούν να αντιγραφούν και να εκτελεστούν.

## 2. Κατασκευή και δοκιμές

Οι απαιτήσεις εξαρτώνται από τον στόχο κατασκευής. Για τη native υλοποίηση απαιτούνται συνήθως μεταγλωττιστής C/C++ (όπως GCC ή Clang) και GNU Make. Η Python 3 χρησιμοποιείται από ορισμένα εργαλεία καταλόγων και αυτοματοποίησης. Τα γραφικά στοιχεία σε Linux ενδέχεται να χρειάζονται τα πακέτα ανάπτυξης X11 και XRandR.

Από τον ριζικό κατάλογο του αποθετηρίου:

```sh
make
```

Κατασκευή της native υλοποίησης και εκτέλεση της πλήρους σουίτας δοκιμών:

```sh
make -C impl all
bash ./test-suites/run-all.sh --all
```

Συνηθισμένοι στόχοι Make:

```sh
make all
make clean
make help
sudo make install
```

Ακολουθήστε τις οδηγίες κάθε επιμέρους στόχου. Η επιτυχής κατασκευή ενός στοιχείου δεν αποδεικνύει ότι όλες οι βιβλιοθήκες ή όλες οι πλατφόρμες είναι έτοιμες για έκδοση. Τα αποτελέσματα πρέπει να διακρίνουν τις δοκιμές που εκτελέστηκαν, παραλείφθηκαν ή απέτυχαν.

## 3. Εγκατάσταση

Η προεπιλεγμένη εγκατάσταση σε επίπεδο συστήματος χρησιμοποιεί συνήθως το πρόθεμα `/usr/local`:

```sh
sudo make install
```

Για εγκατάσταση μόνο στον λογαριασμό του χρήστη:

```sh
make install PREFIX="$HOME/.local"
```

Για δημιουργία ριζικού καταλόγου πακέτου και έλεγχο εγκατάστασης:

```sh
make install DESTDIR="$PWD/package-root"
make install-check
```

Η καθαρή εγκατάσταση παρέχεται μέσω `make clean-install`. Για τις προϋποθέσεις, τα όρια ασφαλείας και τις εναλλακτικές επιλογές, ανατρέξτε στον [οδηγό εγκατάστασης](install/README.md). Βεβαιωθείτε ότι το PATH περιλαμβάνει τον κατάλογο `bin` της επιλεγμένης εγκατάστασης.

## 4. Γλώσσα, μεταγλωττιστής και runtime

Η κανονιστική προδιαγραφή της γλώσσας βρίσκεται στο [SLEELA.syntax](SLEELA.syntax). Η τεκμηρίωση αυτού του αποθετηρίου χρησιμοποιεί τη σύνταξη 3.0. Η έκδοση του μεταγλωττιστή και η έκδοση σύνταξης της γλώσσας είναι διαφορετικές έννοιες. Κάθε χαρακτηριστικό διατηρεί την ελάχιστη έκδοση στην οποία εισήχθη.

Το σύνολο εργαλείων περιλαμβάνει τον μεταγλωττιστή `sleelvac` και το περιβάλλον εκτέλεσης `sleela`. Η τεκμηρίωση καλύπτει, μεταξύ άλλων, τη διάταξη πεδίων `@mix`, εκτεταμένους ακέραιους τύπους, δείκτες εγγράφων Preonem, SleelaDoc, παραγωγή τεκμηρίωσης API και εργαλεία Nordshrift.

Οι διαδρομές εικονικής μηχανής και ενδιάμεσων στόχων περιλαμβάνουν SLVM, SLJVM και SLIR. Ο native στόχος υπόκειται σε χωριστά καθορισμένο όριο διεπαφής. Βασικός κανόνας ασφαλείας: **οι αναφορές προσδιορίζουν· δεν εξουσιοδοτούν την εκτέλεση**. Η ταυτοποίηση ενός αντικειμένου, η εμπιστοσύνη σε αυτό και η άδεια εκτέλεσής του είναι ξεχωριστές αποφάσεις.

## 5. Αρχές μηχανικής και επαλήθευση

Η ανάπτυξη δίνει έμφαση στα τεκμήρια, στα σαφή όρια μεταξύ στοιχείων, στη φορητότητα, στην ασφαλή συμπεριφορά κατά την αποτυχία και στις αναπαραγώγιμες εκδόσεις. Οι συμβάσεις διεπαφών πρέπει να δηλώνουν τις προσδοκίες και τις συνθήκες σφάλματος. Η τεκμηρίωση δεν πρέπει να υπόσχεται δυνατότητες που δεν υποστηρίζονται από τον κώδικα ή τις δοκιμές.

Η επαλήθευση αξιολογείται ανά μονάδα και πλατφόρμα. Έλεγχος που δεν εκτελέστηκε δεν μπορεί να χαρακτηριστεί επιτυχής. Η επιτυχία ενός μεμονωμένου στοιχείου δεν υποκαθιστά τον έλεγχο ολόκληρης της έκδοσης. Οι έλεγχοι SHA-256 και τα manifests ακεραιότητας βοηθούν στον εντοπισμό αλλαγών, αλλά δεν αποτελούν από μόνα τους απόδειξη ασφάλειας.

Τα εργαλεία προστασίας Sleelavirin περιλαμβάνουν τοπική επαλήθευση SHA-256, προαιρετική διασύνδεση ClamAV και manifest ακεραιότητας. Μια έκδοση πρέπει να χαρακτηρίζεται επαληθευμένη μόνο αφού ολοκληρωθούν οι απαιτούμενοι έλεγχοι CI για το συγκεκριμένο commit και εξεταστούν τα παραγόμενα artifacts.

## 6. Επεξεργαστές κειμένου και συνεισφορά

Το SLeeLa παρέχει θέματα και υποστήριξη σύνταξης για Vim και Emacs, καθώς και εργαλεία χρωματικής παλέτας για native C/C++. Δείτε τον [οδηγό ενσωμάτωσης επεξεργαστών](linux-editors/README.md).

Μια καλή συνεισφορά έχει σαφές πεδίο, περιγράφει το σκεπτικό της, περιλαμβάνει θετικές και αρνητικές δοκιμές και αναφέρει το λειτουργικό σύστημα και την αλυσίδα εργαλείων που χρησιμοποιήθηκαν. Οι έλεγχοι που παραλείφθηκαν πρέπει να δηλώνονται ρητά.

## 7. Βιβλιοθήκες και θεματικές του έργου

Το κύριο README καταγράφει τον κατάλογο πακέτων και τις βιβλιοθήκες Advantage, SleelaDoc και XML DOM. Άλλα τεκμηριωμένα θέματα περιλαμβάνουν βασικούς ακέραιους τύπους, runtime χαρακτήρων, AutoCAD Creator™, το πειραματικό ευρετήριο UTF-4088, τη σταθερά Pi, τα Modium™ και Registry™, καθώς και το εργαλείο `sleelactl`.

Το πειραματικό ευρετήριο UTF-4088 ενός εκατομμυρίου εγγραφών και τα συναφή πειραματικά δεδομένα πρέπει να ερμηνεύονται σύμφωνα με την αντίστοιχη τεκμηρίωσή τους. Η ύπαρξη ενός καταλόγου δεν σημαίνει αυτομάτως ότι κάθε εγγραφή χρησιμοποιείται σε παραγωγή. Η συντήρηση του καταλόγου πακέτων πρέπει να διατηρεί την ιχνηλασιμότητα διαδρομών, ιδιοκτησίας, εξαρτήσεων και κατάστασης δοκιμών.

## 8. `@native` και η διαδρομή προς C/C++

Η τεκμηρίωση περιγράφει το γνώρισμα `@native` και την εντολή `sleela aot` ως πρώτο στάδιο της διαδρομής από πηγαίο κώδικα SLeeLa προς native C/C++. Αυτό δεν αποτελεί απεριόριστη άδεια native εκτέλεσης. Παραμένουν ουσιώδη τα όρια διεπαφής, το ABI, η ρητή έγκριση και οι πύλες ασφαλείας. Η πραγματική κατάσταση του στόχου πρέπει να ελέγχεται στην υλοποίηση και στις δοκιμές.
