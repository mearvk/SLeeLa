SLeeLa Foundational API Reference

This reference defines the foundational API families that a general-purpose software system should expose through SLeeLa and documents where the corresponding SLeeLa source already exists in this repository.

Documentation rule: an entry is marked implemented only when this repository contains a corresponding source surface. A general software API family may also be listed as a target category when SLeeLa does not yet have a complete implementation. This page does not invent classes, functions, or guarantees.

Foundational class families

The class families below are the stable conceptual building blocks for the API documentation. Where SLeeLa already has concrete classes, the family points to those source declarations; where it does not, the family remains a documented target rather than an invented implementation.

  • Value and data: String, ByteBuffer/byte sequence, numeric values, Boolean, collections, maps, records and structured values.
  • I/O: InputStream, OutputStream, Reader, Writer, Buffer, Console and channel-style abstractions.
  • Files: Path, File, Directory, FileInfo/metadata, FileChannel and file-system service abstractions.
  • Networking: Address, Socket, ServerSocket/Listener, Connection, NetworkChannel, DNS resolver, HTTP request, HTTP response and Router.
  • Security: Digest, MAC, Key, KeyAgreement, Identity, Certificate/TLS configuration and integrity-verification services.
  • Email: EmailMessage, EmailAddress, SMTP client/transport, mail configuration and email server/client integration.
  • GUI: Application, Window, Document, Event, Widget, Layout, Menu, Dialog, Control and GUI runtime/host.
  • Processes: Process, ProcessBuilder/executor, Environment, ExitStatus and child-process streams.
  • Concurrency: Thread, Mutex/Lock, Condition, Future/Task and Executor-style services.
  • Time: Instant, Duration, Clock, Timer and scheduling services.
  • Persistence: Database, Connection, Transaction, Query, ResultSet/record set, Repository and serialization.
  • Distributed systems: Remote, Endpoint, Client, Server, Service, Session and invocation context.

Coverage relationship

API.html remains the repository-wide source-unit catalog. SOURCE-COVERAGE.html remains the exhaustive file inventory. This page is the foundational semantic map: it organizes the repository's source into the general-purpose API families a programmer expects from a software platform.
