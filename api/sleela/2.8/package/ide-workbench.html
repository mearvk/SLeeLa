Defines SLIdeDiagnosticsPanel — the surface that renders compiler diagnostics inside the IDE. SLIdeTabGroup class

Defines SLIdeTabGroup — the multi-document (tabbed) model lib/gui lacks. SLGuiWindow is a single-text window and SLGuiDocumentListener is hard-bounded to 1..14 watched documents; a real IDE opens many files. This group owns an unbounded set of SLIdeEditor buffers and tracks the active one, while exposing only the active + most-recently-focused editors (<= SLGUI_MAX_DOCUMENTS) to be registered with the OS watch. The 1..14 bound stays an OS-watch contract; the open-file count is independent of it.

SLIdeWorkbenchUI #sleela 2.5 (lib/ide-workbench/SLIdeWorkbenchUI.sleela)

SLIdeWorkbenchUI class

Defines SLIdeWorkbenchUI — the IDE shell rendered as a REAL SleelaUI graphical interface, built on the /lib/gui support structure. The shell's chrome (the window, header bar, and the Open/Compile/Save/Close command buttons) is expressed as an SLGuiApp DOM: each command is a DOM button node with an onClick handler bound through the event bus, so a real click flows widget -> SLGuiHostAdapter -> SLGuiEvent -> handler -> command, instead of ad-hoc .clicked() polling. The rich content controls (the SLTreeView project explorer, the SLNotebook of SLTextView code editors, and the SLLoadingIndicator) are specialised SleelaUI widgets mounted into the DOM's body/status container handles. SLGuiApp runs the loop (pump -> poll activations -> dispatch -> reconcile); this class only reads the command handler latches and acts. The IDE is the first full consumer of the event/DOM/support stack. Family: ide-workbench. The GUI is SleelaUI driven through the lib/gui DOM; SLeeLa owns meaning and dispatch.
