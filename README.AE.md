# SLeeLa 3.0 — الإمارات العربية المتحدة (AE)

## النسخة العربية

SLeeLa لغة برمجة أنظمة أصلية، مع مُصرّف وبيئة تشغيل ومنظومة من الآلات الافتراضية. يضم المشروع اللغة وأدوات البناء والمكتبات وعقود التكامل مع المنصات. تحافظ هذه النسخة على أسماء الملفات والمعرّفات والأوامر ومقاطع الشيفرة وأسماء واجهات API كما هي لتظل التعليمات قابلة للتنفيذ.

**The Now. The Ingredient.** اللغة ليست قواعد نحوية فحسب؛ إنها منظومة متكاملة تشمل المُصرّف وبيئة التشغيل والمكتبات والأدوات وعقود المنصة.

يقسم المشروع مجالات عمله إلى **Math** و**Object** و**Science** و**Reach**. وتظل المصالح الوطنية ذات الصلة مسجلة في بيانات وصفية صريحة، ولا تُلغى بسبب هذا التقسيم.

## II. أبرز المستجدات والميزات

تتضمن مكتبة SLeeLa القياسية حزمة **Advantage** (`lib/advantage/`) لتحليل توزيعات الأرباح نسبةً إلى نموذج، ببنية طبقية تشمل المراجعة والمخاوف والرياضيات والإضافات والطرح وإعادة التجميع والتكرار. تشمل موضوعاتها رياضيات التفاوض الثنائي، ونموذجًا اقتصاديًا بنيويًا لحقول الثقة (وهو تشبيه نمذجي معلن)، والتكامل الرأسي، وتقييم الوحدات، وإخراج النتائج إلى الطرفية أو CommonRails أو موصلات الشبكة. راجع [Advantage](lib/advantage/README.md).

تشمل الميزات الموثقة كذلك:

- **توقيت الحلقات:** تتيح `@loopDelay` و`@loopBudget` تحديد فترات التوقف والميزانيات الزمنية للحلقات. ويستخدم التنفيذ `OP_SLEEP` و`sleep(ms)`. راجع [المواصفة §32](SLEELA.syntax) و[واجهة Loop Timing](api/sleela/3.0/LOOP_TIMING_API.md).
- **SleelaDoc:** توثيق مصدر الشيفرة وإنشاء صفحات Markdown وHTML وفهرس الموضوعات ومرجع API. يدعم الأمر `sleela docs` عرض الموضوعات والحزم والفئات. راجع [SleelaDoc](lib/sleeladoc/README.md).
- **XML DOM:** شجرة عقد XML مع عناصر ونصوص وتعليقات وCDATA وتعليمات معالجة، وسمات مرتبة، ومحلل ومُسلسل XML 1.0. راجع [XML DOM](lib/xml/README.md).
- **أنواع الأعداد الصحيحة:** تشمل الأنواع `long` و`int64` و`int128` وعائلات صحيحة موقعة وغير موقعة. يجب الرجوع إلى المواصفة لمعرفة السعة الفعلية؛ فالاسم وحده لا يضمن عرضًا معينًا.
- **حقول `@mix`:** تسمح بتجميع حقول مثيل متكررة الاسم في تسلسل مفهرس، مع فهارس تلقائية أو يدوية وفق قواعد المواصفة.
- **علامات Preonem:** علامات وثائقية مثل `author` و`authorial` و`material` و`memory` و`determine` و`object` و`field`. يتحدد معناها من موضعها وإصدار الصياغة؛ وخارج موضع العلامة تظل معرّفات عادية.
- **Nordshrift:** يحل الحزم ووحدات المصدر بالاعتماد على الفهرس التكراري نفسه لمجلد `/lib`.
- **تعليقات الأقواس الزاوية:** الصيغتان `< ... >` و`<< ... >>` موثقتان كأنماط للتعليق.
- **الأعداد ذات الأساس:** تدعم القواعد صيغ الأعداد الست عشرية والثنائية والثمانية وفواصل الأرقام.

المواصفة [`SLEELA.syntax`](SLEELA.syntax) هي المرجع الحاكم لقواعد اللغة. ولا يعني ظهور ميزة في وصف عام أنها متاحة في كل إصدار من المُصرّف.

## III. البناء والاختبار

**المتطلبات:** سلسلة أدوات C/C++ مثل GCC أو Clang، وGNU Make، وPython 3 لأدوات البيانات الوصفية وسير العمل. وقد تتطلب منتجات العرض على Linux حزم تطوير X11/Xrandr. راجع وثائق الوحدة لمعرفة متطلباتها المحددة.

من جذر المستودع:

```sh
make
```

لبناء النواة الأصلية وتشغيل مجموعة الاختبارات:

```sh
make -C impl all
bash ./test-suites/run-all.sh --all
```

أهداف Make الشائعة:

```sh
make all
make registry
make tests
make ballum
make help
make clean
```

يبني الهدف الجذري المنتجات التي يوزعها المستودع، ويشمل هدف `registry` بناء نواة السجل وإنشاء جدولها المرجعي. راجع [دليل Registry](registry/README.md) و[معمارية Registry 3.0](registry/REGISTRY-3.0-ARCHITECTURE.md).

نجاح بناء مكوّن واحد لا يثبت جاهزية جميع المكتبات أو المنصات للإصدار. يجب تقييم التحقق لكل وحدة ومنصة. ولا يجوز وصف الاختبارات المتجاوزة أو غير المنفذة بأنها ناجحة.

## IV. التثبيت

```sh
sudo make install
make install PREFIX="$HOME/.local"
make install DESTDIR="$PWD/package-root"
make install-check
```

يستخدم التثبيت التقليدي عادةً `/usr/local/bin` و`/usr/local/lib/sleela` و`/usr/local/share/sleela`. يتيح `PREFIX="$HOME/.local"` التثبيت ضمن حساب المستخدم، وغالبًا دون `sudo`. أما `DESTDIR` فينشئ شجرة تجهيز للحزم دون تثبيت مباشر في النظام.

لتثبيت الحزمة الرئيسية الموجه فقط، بما فيها `sleela` و`sleelvac` و`nordshrift` والمكتبة القياسية والبروتوكولات ووحدات الدعم:

```sh
make clean-install
```

راجع [دليل التثبيت الآمن والسريع](install/README.md). يحافظ المثبّت على إعدادات بدء التشغيل القائمة ويتجنب استبدال الأوامر غير المسجلة لديه. وينبغي أن تقتصر الإزالة على الملفات التي سجلها المثبّت.

## V. اللغة وبيئة التشغيل

تعتمد وثائق المستودع صياغة **SLeeLa 3.0**. إصدار المُصرّف وإصدار صياغة المصدر مفهومان منفصلان. تجمع صياغة 3.0 الميزات المتراكمة من الإصدارات 1.0 إلى 2.9 مع الاحتفاظ بالحد الأدنى لإصدار كل ميزة.

منظومة المشروع تضم مُصرّفًا وبيئة تشغيل وآلات افتراضية وأدوات توثيق ومكتبة منظمة في حزم. وتوجد ملفات التنفيذ الأصلية C وC++ إلى جانب وحدات SLeeLa. يجب احترام عقود ABI الموثقة عند عبور الحدود بين الشيفرة الأصلية وبيئة التشغيل.

## VI. C وC++ والترجمة الأصلية

تمثل `@native` و`sleela aot` مرحلة أولية ومحافظة من مسار الترجمة المسبقة. يمكن فحص الطرق الموسومة وإصدار C/C++ للحالات التي تقع ضمن مجموعة فرعية مدعومة:

```sh
sleela aot --list <file.sleela>
sleela aot --emit <file.sleela>
```

تُرفض البنى غير المدعومة مع توضيح السبب بدل إنتاج ترجمة جزئية مضللة. ولا يغير الوسم `@native` سلوك البرنامج بمفرده. ولا ينبغي اعتبار بناء مكتبة مشتركة أو إرسال التنفيذ إليها من VM ميزات مكتملة دون أدلة تنفيذ واختبارات. راجع [AT-NATIVE](pi-generator/AT-NATIVE.md).

## VII. المكتبات والأنظمة الفرعية

- **CPU** (`lib/cpu/`): نماذج المعالجات وملفات التعريف والتنفيذ والتوقيت.
- **Ballum** (`ballum/` و`lib/ballum/`): تحكم على مستوى البكسل وإدارة المناطق والسطوع وGamma وإدخال لوحة المفاتيح والمؤشر؛ ويعتمد التوفر على النظام والواجهة الخلفية. [Ballum](ballum/README.md).
- **AutoCAD Creator™** (`autocad/creator/`): تطبيق CAD ثنائي الأبعاد لإنشاء الكيانات والطبقات والأبعاد والملاحظات والتراجع وحفظ رسومات DXF. النموذج هو المرجع الهندسي وسجل التعديلات؛ الواجهة تعرضه. [AutoCAD Creator](autocad/creator/README.md).
- **Alphabet وUTF-4088:** أدوات فهرسة الأحرف وتجارب ترميز. UTF-4088 يستخدم فضاء معرّفات خاصًا به و**ليس متوافقًا مع Unicode**؛ لا تخلط بين معرّفاته والقيم القياسية Unicode.
- **Pi Generator:** أدوات لقيم π والتحقق وإعادة الإنتاج.
- **Modium وRegistry:** أنظمة السجل وأدوات الفحص.
- **Philosophy:** وحدات بيانات ومساعدة ومحادثة. توصف وحدة المحادثة بأنها غير سريرية وتعتمد على المدخلات الصريحة والموافقة؛ ولا تقدم تشخيصًا طبيًا.
- **CDMA وOFDMA وHTTP وWi-Fi:** مجالات تقنية ومكتبات ذات إصدارات. راجع وثائق كل حزمة لمعرفة نطاقها وحالة اختبارها.

فهرس الحزم وصفي ولا يحل محل README والاختبارات الخاصة بكل وحدة.

## VIII. النزاهة والأمن والتحقق

يوثق المشروع بيانات SHA-256 للتحقق المحلي من سلامة الملفات، وموائمًا اختياريًا لـ ClamAV عبر Sleelavirin. وجود أداة أو بيان سلامة لا يشكل بمفرده شهادة أمنية.

مبادئ الهندسة:

1. عقود واضحة بين المكونات.
2. مراعاة قابلية النقل منذ التصميم.
3. سلوك آمن عند فشل العملية.
4. أدلة قابلة لإعادة الإنتاج ومرتبطة بالتزام Git الذي جرى اختباره.
5. التمييز بين تحديد مرجع والتصريح بتنفيذه.
6. بيان الاختبارات غير المنفذة أو المتجاوزة بوضوح.

لتقييم الإصدار، راجع نتائج CI الخاصة بالتزام المحدد والملفات الناتجة والاختبارات ومصفوفة المنصات. لا تعمم نتيجة Linux على Windows أو macOS دون دليل منفصل.

## IX. المحررات والمساهمة

تتوفر تكاملات الصياغة والسمات لـ **Vim** و**Emacs**، إضافة إلى أداة لوحات ألوان C/C++. راجع [دليل المحررات](linux-editors/README.md).

للمساهمة:

1. اقرأ [فهرس الوثائق](docs/README.md) و[سياسة الاختبار](markdown/TESTING.md).
2. اجعل التغييرات محددة النطاق وأضف اختبارات إيجابية وسلبية.
3. شغّل الاختبارات ذات الصلة ثم المجموعة الأوسع المناسبة.
4. سجل نظام التشغيل والمُصرّف وسلسلة الأدوات المستخدمة.
5. لا تصف الاختبارات المتجاوزة بأنها ناجحة.

تتولى **MEARVK LLC** تطوير SLeeLa.

## X. موضوعات وموارد إضافية

يتضمن README الرئيسي أيضًا CSPML ومصادر بياناته وإرشادات التكامل، ومراجع الأبحاث، ومفاهيم البضائع والأصول البصرية، إضافة إلى فهرس الحزم مثل Character وGovernance وSynchro وSleelaUI وUnited Nations. هذه المراجع تصف محتويات المشروع ولا تمثل اعتمادًا حكوميًا أو مؤسسيًا.

يتضمن المستودع كذلك قسمًا بعنوان **Bitcoin Conjegeum** يحوي عناوين ومواد رسومية. وجود تلك البيانات لا يشكل توصية مالية أو تحققًا من الملكية أو توجيهًا لتحويل الأموال. تحقق من المعلومات بصورة مستقلة قبل استخدامها.

## XI. أداة توثيق API وإنتاج المستندات

يمكن استخدام `sleela docs` لاستعراض الموضوعات والحزم والفئات، كما يمكن إنشاء مجموعة وثائق نصية للعمل دون اتصال. تستخدم SleelaDoc وسومًا توثيقية مثل `@intent` و`@thesis` و`@axiom` و`@param` و`@see` و`@mastery`. راجع [دليل SleelaDoc](lib/sleeladoc/README.md) و[الموقع المُولّد](sleeladoc-api/README.md).

## XII. AutoCAD Creator™

يوفر AutoCAD Creator™ تحرير رسومات CAD ثنائية الأبعاد، بما في ذلك إضافة الجدران والغرف والأبعاد والملاحظات وتحريك العناصر وتغيير الطبقات والحذف والتراجع وحفظ ملفات DXF النصية. تستخدم الواجهة SleelaUI™ ويمكن أن تفتح نوافذ أصلية عبر X11 أو Cocoa أو Win32 وفق النظام.

المبدأ المعماري هو: **SleelaUI تعرض؛ وSLeeLa تقرر.** يتولى نموذج `SLCadCreator` هندسة المستند وسجل التعديلات القابل للعكس، وليس طبقة العرض.

```sh
make creator
```

شغّل الأمر من `autocad/`. وفي بيئة بلا شاشة يمكن للمثال إنشاء الرسم في الذاكرة وإصدار تقرير ثم الإنهاء.

## XIII. كتالوج UTF-4088 التجريبي

ينتج المولد `utf-4088/tools/generate_catalogue.py` كتالوجًا تجريبيًا حتميًا يضم **1,048,576** مدخلًا. يبلغ حجم الملف الثنائي الموصوف 16,777,244 بايت. تتحقق الاختبارات وسير عمل GitHub Actions من عدد المدخلات وتفرّد الرسوم والحجم وSHA-256. يُنشر الملف الثنائي كأثر لسير العمل بدل إضافته إلى سجل Git. يظل UTF-4088 تجريبيًا وغير متوافق مع Unicode.

## XIV. π وModium وRegistry وsleelactl

يوثق المستودع مجموعة أرقام عشرية لـ π، منها مجموعة من **100,000,000** رقم وأخرى من 57,344 رقمًا. يشرح [VERIFIED](pi-generator/VERIFIED.md) عمليات الفحص وإعادة الإنتاج.

تستطيع نقاط الدخول `sleela registry` و`sleela modium` تحميل كتالوج π عند بدء التشغيل. يضيف المثبّت الموجّه `sleelactl` وسجل الوحدات. ويصف المشروع `math` بوصفه أول subject لمكتبة C/C++ أصلية متكاملة مع runtime؛ راجع معلومات الوحدة وأوامرها في وثائق المشروع.
