# Synchro 1-2-3-4

## 1 — Protocol

Establish one unambiguous wire contract: 16 bytes, SYNC magic, network-order
sequence, monotonic timestamp, strict short/magic validation, local RTT
measurement, timeout-as-loss, nearest-rank percentiles, and observation-only
SLA reporting.

**Exit:** C, C++, and Java agree on the packet contract.

## 2 — Language / VM Integration

Use the C integration ABI for prepare/ack/timeout/statistics; C++ owns that ABI
through RAII; Java provides its host-language boundary; existing VM OP_SYN_*
operations remain the runtime surface. Adapters must preserve one protocol and
statistics model.

**Exit:** a VM Synchro operation traces through the same semantics as C.

## 3 — Verification

Cover normal ACK, timestamp fallback, timeout/loss, invalid magic, short packet,
wrong sequence, duplicate ACK, timestamp rollback, statistics windows, C++
runtime behavior, Java integration, and the end-to-end VM/UDP/SLA path.

**Exit:** deterministic local tests pass and network tests report measurements.

## 4 — Platform / Release

Verify Linux, macOS, and Windows C/C++ builds; document Java build/test;
maintain ABI/version documentation; and publish CI coverage for supported
platforms.

**Exit:** every supported build path compiles and exercises Synchro without
manual source assembly.

## Current position

Protocol, C/C++ integration, existing VM operation surface, native Makefile
wiring, and baseline documentation are present. Remaining work is concentrated
in negative protocol coverage, VM end-to-end execution, Java build automation,
and multi-platform/CI verification.
