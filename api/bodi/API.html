SLeeLa BODI XML API Reference

The BODI XML runtime reads a bounded XML project and turns its declared operations into witnessed, deterministic SLeeLa API calls. XML is a project representation; it is not arbitrary native-code execution.

Envelope

<bodi version="1">
  <project id="..." kind="science|email|media"/>
  ...
</bodi>

Audio / Video / Image media projects

BODI may declare kind="media" for bounded media analysis and provider selection. Audio and video codec families, containers, and image formats are named explicitly so a runtime can select an installed provider without changing the native frame ABI.

<audio codecs="pcm,aac,flac,mp3,opus,vorbis"/>
<video codecs="h264,hevc,av1,vp8,vp9" containers="mp4,mkv,webm"/>
<image formats="jpeg,png,gif,webp,avif,heif"/>

The base runtime recognizes these families. Actual decode/encode is provider-dependent and must be checked at runtime.

Science projects

A science project contains one or more discipline elements. Supported executable disciplines are math, physics, chemistry, and data-analytics.

Media listener boundary

Media XML files may be admitted from a configured folder through a listener. Each document is size-limited, parsed, validated against the supported media vocabulary, and then queued. XML does not itself acquire unrestricted device, shell, or native-call authority. Future AI providers attach through the native media-frame hook.

Execution boundary

The runtime performs an allow-listed operation dispatch. Unknown elements, operations, malformed numbers, and excessive input are rejected. XML cannot invoke shell commands or arbitrary native functions.
