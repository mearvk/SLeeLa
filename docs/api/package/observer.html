ObserverDemo class

Runnable, self-checking demonstrator for the dynamic document observer (lib/observer). SLDocumentObserver #sleela 2.5 (lib/observer/SLDocumentObserver.sleela)

SLDocumentObserver class

Defines SLDocumentObserver — a dynamic document observer. Modules are admitted through bounded ports WHILE THE PROGRAM IS RUNNING; when the standing document changes every active module is told, and may answer, converse with the others, or PROPOSE an edit. The observer is the only writer of the document, and it applies a proposal only if it is based on the current revision, within the per-cycle and depth budgets, and accepted by the document. Hop limits bound conversations, repeated faults quarantine a module, and everything is written to a bounded audit trail. Drive it as a cycle: edit(...) delivers the change; then while beginCycle() is true, pump every module, then endCycle() routes what they said. beginCycle() is false when nobody has mail or the cycle cap is hit.

Carries the standard Metadata Class record — eleven catalogued provenance attributes (version, id, author, date, copyright, trademark, corporation, origin, birth date, science rating, national schedule) with matching get/set accessors. These are omitted from the tables below for brevity.

SLObserverMessage class

Defines SLObserverMessage — the one envelope the dynamic document observer and its modules speak. A message is a NOTE, QUESTION, ANSWER, PROPOSE, FAULT, or CHANGE; CHANGE is what the observer sends when the standing document moves, and the rest are how modules converse with the observer and with each other. The observer stamps the sender on routing so a module cannot impersonate another.
