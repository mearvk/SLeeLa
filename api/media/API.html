SLeeLa Audio and Video API

The media API treats audio and video as timestamped native frames and separates native frame analysis from codec/container providers. This keeps the core ABI small while allowing a broad set of known media formats to be added by built-in or drop-in providers.

Images

The format registry recognizes BMP, JPEG/JPG, PNG, GIF, APNG, WebP, TIFF, JPEG 2000, JPEG-LS, AVIF, HEIF/HEIC, OpenEXR, Radiance HDR, PAM, PNM and DPX image families.

Video

The registry recognizes H.263, H.264/AVC, H.265/HEVC, AV1, MPEG-1, MPEG-2, MPEG-4 Part 2, Theora, VP8, VP9 and FFV1 video codecs. Common containers include MP4, Matroska/MKV, WebM, Ogg, MPEG-TS, QuickTime/MOV, AVI and 3GP.

Audio

The registry recognizes PCM, AAC, ALAC, AMR, FLAC, G.711, G.722, MP3, Opus and Vorbis. Common containers include WAV, AIFF, FLAC, MP3, MP4, Ogg, WebM, MKV and ADTS.

Runtime provider model

SLMediaProviderInfo lets a native provider advertise decode/encode support for a codec, container or image family. This permits FFmpeg, platform-native media stacks, hardware codecs, or another compatible provider to be connected without changing the frame-analysis ABI. Runtime selection should check provider availability before decode or encode.

Processing

Listeners and transforms operate on decoded frames. Audio analysis provides level, peak and RMS with a spectrum extension; video analysis provides luminance, edge density and a motion field reserved for frame-to-frame monitoring.

AI extension

SLMediaAIHook remains a provider boundary for future audio/video AI input and output. AI providers can receive normalized native frames after decoding rather than depending on one file codec.
