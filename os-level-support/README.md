# OS Level Support

Portable C ABI with a thin C++ facade and a typed SLeeLa VM binding adapter for read-only, user-mode host services that complement the SLeeLa standard OS model. Existing APIs cover host/process facts, environment, filesystem metadata, CPU/memory, timezone, network metadata, and cron calculation; platform gaps are returned explicitly.

The `runtime/` subdirectory adds an initial, deterministic, in-process C/C++ event-hook registry and cooperative task queue. Hooks are callbacks registered by this runtime only; they do not intercept OS/system calls. Tasks execute only when the caller pumps the queue. This initial layer does not create threads or processes, launch commands, perform I/O, install OS schedules, or alter platform configuration. Callback payloads and user-data remain caller-owned.

The `trust/` directory contains the Global Ring of Trust concept and a C/C++ structural claim model. A well-formed claim is **unverified** and non-authorizing; this code does not perform cryptography, identity verification, revocation lookup, or privilege decisions.

The library intentionally excludes syscall interception, kernel hooks or memory access, driver installation/removal, registry/configuration mutation, privilege elevation, and trust-based authorization. The `osls_vm_bridge.c` registry exposes 12 stable VM operations through `OP_OSLS_CALL` (155). Each entry binds a stable native symbol identity to a callable function pointer, typed argument signature, JSON UTF-8 result type, and required host-read capability; embedding hosts can grant or revoke that VM-local permission with `slvm_set_osls_capabilities` (read-only inspection is the default). The VM validates stack value tags before invoking the registered function and returns bounded JSON Strings for records and collections. The VM Makefile also compiles this adapter into `sleela` and `sleelvac`. Build and test with `cmake -S os-level-support -B build/osls`, `cmake --build build/osls`, and `ctest --test-dir build/osls --output-on-failure`.
