SLeeLa Posting, Listener and Router API

This API gives the XML project system a concrete C vocabulary for basic HTTP-style posting, listener declarations, and route matching. Validation is bounded and does not execute network operations by itself.

Post

sleela_post_t describes a POST method, an absolute target path, a content type, and a body. sleela_post_validate() checks the contract; sleela_post_write() emits a bounded HTTP/1.1-style request representation to a file descriptor.

Listener

sleela_listener_t describes a bind host, port, protocol, and route. The current C facade validates the listener contract; socket lifecycle and platform adapters remain separate.

Router

sleela_route_t describes method/path to target-path routing. sleela_router_match() performs exact matching, providing a deterministic base for a higher-level router.

Security boundary

These facades do not execute shell commands or interpret XML as native code. Network binding, external delivery, authentication, and authorization must be explicit higher-level operations.
