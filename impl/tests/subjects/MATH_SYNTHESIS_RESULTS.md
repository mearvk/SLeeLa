# SLeeLa Native Math Synthesis CI

Generated by the native math synthesis workflow.

## Test sequence

1. Generate a checkout-specific SHA-256 manifest.
2. Build the SLeeLa runtime and compiler with make -C impl all.
3. Inspect and execute the native Math subject through bin/sleelactl.
4. Run impl/tests/subjects/math_values.sleela, which imports math and checks known numerical results.
5. Repeat the accuracy program seven times and record per-run wall-clock timing, mean, median, range, and aggregate assertion throughput.

The Math subject is a native subject, not a registry. Its supported sleelactl execution verb is run, which dispatches its reference demo; the test program independently exercises import math; and the public math functions.

## Measurement notes

Timings include runtime startup, source loading, program execution, and output capture. They are end-to-end smoke measurements, not isolated function microbenchmarks. Compare results on the same GitHub-hosted runner class. Every timing sample is retained in the generated report.
