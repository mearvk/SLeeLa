SLeeLa BODI XML API Reference

The BODI XML runtime reads a bounded XML project and turns its declared operations into witnessed, deterministic SLeeLa API calls. XML is a project representation; it is not arbitrary native-code execution.

Envelope

<bodi version="1">
  <project id="..." kind="science|email"/>
  ...
</bodi>

Science projects

A science project contains one or more discipline elements. Supported executable disciplines are math, physics, chemistry, and data-analytics. The data-analytics shelf provides bounded numeric statistics and correlation operations for scientific data sets. The schema also reserves descriptive discipline names such as chemistry, biology, astronomy, earth-science, computer-science, and engineering for future native handlers.

Operations use named functions and numeric arguments. Examples include data-analytics.mean, data-analytics.variance, and data-analytics.correlation. Examples also include chemistry.ratio, chemistry.similarity, math.sqrt, math.pow, math.sin, physics.velocity, physics.force, physics.kinetic_energy, physics.gravitational_force, physics.ohms_voltage, and physics.electric_power.

Audio / Video media projects

BODI may declare kind="media" for bounded audio/video analysis. Audio supports level, RMS, peak and spectrum extension; video supports luminance, edges and motion analysis. A media listener may watch a configured drop-in folder for validated XML transformation documents. These declarations connect to native timestamped media frames rather than arbitrary native execution.

<bodi version="1">
  <project id="media-monitor" kind="media"/>
  <audio analysis="level,rms,peak,spectrum"/>
  <video analysis="luminance,edges,motion"/>
</bodi>

Posts, listeners and routers

BODI projects may declare kind="post", kind="listener", or kind="router". A <post> describes an HTTP-style POST. A <listener> declares bind host, port, protocol, and route. A <router> contains deterministic method/path-to-target route entries.

The native C vocabulary is provided by sleela_post_t, sleela_listener_t, and sleela_route_t. The XML runner validates and witnesses these declarations; it does not implicitly open sockets or transmit network traffic.

Email / SMTP projects

An email project declares an SMTP endpoint and a message. The password must be supplied by an environment variable through password-env; credentials are not intended to be stored in XML.

Supported TLS modes map directly to the existing Email Facade: none, starttls, and implicit. The runner requires --send-email before it performs network submission.

Media listener boundary

Media XML files may be admitted from a configured folder through a listener. Each document is size-limited, parsed, validated against the supported media vocabulary, and then queued. XML does not itself acquire unrestricted device, shell, or native-call authority. Future AI providers attach through the native media-frame hook.

BODI witness

Every executed project operation produces a witness record containing project identity, sequence, discipline, operation, result, and status.

Execution boundary

The runtime performs an allow-listed operation dispatch. Unknown elements, disciplines, operations, malformed numbers, and excessive input are rejected. XML cannot invoke shell commands or arbitrary native functions.
