# Model record — 27C256 (Corrado ECU EPROM)

Per-device record for the standard Corrado engine-ECU memory part, using the
`TERMINOLOGY.md` value classes (Actual / Assumption / Default / Unknown).

## Identity

| Property | Value | Class |
|----------|-------|-------|
| Device | 27C256 | Actual |
| Organisation | 32768 × 8 (256 Kbit) | Actual |
| Package | 28-pin DIP, socketed on the ECU board | Actual |
| Supply | +5 V, TTL-level programming | Actual |
| Erase | UV-erasable; often one-time-programmable | Actual |

## Host-image mapping

| Property | Value | Class |
|----------|-------|-------|
| Image size | 32768 bytes | Actual |
| Blank cell | 0xFF | Actual |
| Checksum | trailing 2-byte little-endian word (16-bit reconciliation) | Actual |
| Reference images | `Corrado/eproms/G60_StockEprom_REFERENCE.bin` (checksum16 0x60A0), `.../VR6_...bin` (0xE41C) | Verified (software) |

## Operations

| Verb | Supported | Note |
|------|-----------|------|
| read / backup | Yes | chip → image / file |
| write (+verify) | Yes | program then read-back verify |
| verify | Yes | compare chip to a file |
| blank-check | Yes | confirm all 0xFF |
| checksum | Yes | file-only; no hardware needed |
| erase | **Conditional** | UNSUPPORTED on genuine UV/OTP 27C256 (use a UV eraser); succeeds only on reusable pin-compatible replacements |

## Evidence boundary

The read/write/verify/checksum paths are verified in software against the
reference images and the fake backend. Live-chip programming of a physical
27C256 is **not** recorded here; see `../../docs/COMPLETENESS.md`. Do not treat
the TL866 bulk framing as a verified hardware value until checked against a
physical unit.
