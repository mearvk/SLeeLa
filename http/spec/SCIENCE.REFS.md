## Public Contact and Network Verification Registry

The following fields extend the reference without implying that a listed institution operates a PCC or Science Router node.

**Verification rules:**

- **Official website** means a publicly identified institutional website. A website alone does not establish a network-routing role.
- **Public contact email** means an address publicly published by the institution or a clearly authoritative institutional source. Personal addresses are intentionally excluded from this registry unless they are explicitly published as an institutional contact point.
- **Public IP / ASN** is not treated as a permanent institutional identity. Web properties may use CDNs, cloud providers, reverse proxies, shared hosting, or changing addresses. Therefore this registry does not record raw IP addresses as Science Router identities.
- **Known router** is recorded only when an institution publicly and explicitly identifies a router or networking role. No router is inferred from the existence of a website, Wi-Fi service, ISP, DNS record, or ordinary Internet connectivity.
- **Science Router status** is therefore `Not verified` unless the institution has independently and publicly designated a Science Router / Science Hub function.

### Network and Router Safety Boundary

The HTTP 3.0 Science Router registry must distinguish **public institutional identity** from **network reconnaissance**.

This document may record publicly published institutional websites, published general-purpose contact addresses, public organization identifiers, and explicit institutional statements about participation in a Science Router / Science Hub program. It should not become a directory of private infrastructure, management interfaces, internal topology, firewall addresses, router addresses, administrative credentials, or other network-reconnaissance data.

Accordingly:

1. A domain name is an institutional reference, not a router address.
2. A public website IP may change and may represent a CDN, reverse proxy, cloud host, or shared service rather than the institution's own network.
3. A DNS record does not establish that a host is a Science Router.
4. A Wi-Fi access point, firewall, ISP gateway, or ordinary edge router does not become a PCC Registered Router merely because it is reachable from the Internet.
5. A Science Router designation requires explicit authorization and a documented PCC registration role.
6. Ancillary Science Router data should use the protected Science Router / Science Hub mechanisms defined elsewhere in this specification set.
7. Unknown values are deliberately recorded as **Not publicly verified** rather than inferred.

### Verification Classes

| Class | Meaning |
|---|---|
| `CONTACT-VERIFIED` | Official website and/or institutionally published contact information verified. |
| `WEBSITE-VERIFIED` | Official website identified, but a suitable public contact email was not independently verified in this pass. |
| `CONTACT-PENDING` | Institution is in the registry but contact verification remains to be completed. |
| `NETWORK-NOT-VERIFIED` | No public Science Router or authorized PCC router role has been established. |
| `ROUTER-AUTHORIZED` | Reserved for a future entry backed by explicit institutional authorization and PCC registration documentation. |

### Reference and Use

The source table includes institutional location and AAM/ASTC participation fields. The source itself describes the list as dynamic and potentially incomplete. This SLeeLa reference is intended to support future Science Router and Science Hub mapping; inclusion does **not** imply that an institution currently operates a network router, participates in PCC, authorizes packet registration, or has agreed to receive ancillary data.

Future entries should be independently verified before being promoted from a reference entry to an operational Science Router or Science Hub designation.
